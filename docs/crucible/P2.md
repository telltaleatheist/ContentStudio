## The rules, as built

**One door, two branches in makeRequest.** `claude-cli:` goes to `claude -p` exactly as before;
everything else to `transport.chat`, which refuses a stale `ollama:`/`claude:`/`openai:` string by
name. `runPlainRequest(prompt, model, what, shape)` gains its fourth argument (deviation 1).

**Per call (plan 6.3).** `thinking` stated on every body (`chat_template_kwargs.enable_thinking`;
Crucible drops it for Anthropic and says so); field calls, description, stage 1, name scaffold,
distiller, more titles, story titles, summarizer and compilation package OFF; chapter detail,
scrub and Soften ON. Budgets are today's (P4 lowers them). No temperature/top_p/top_k ever reaches
an `anthropic/` body (refused `sampling_to_cloud` if a caller tries); stage 1's 0.7 is local only.
Every Anthropic call sends `max_tokens` 16000 (a different number is refused). The compilation
package asks a local model for `response_format: json_object`; on cloud its JSON contract stays in
the system turn (a `json_schema` would become a forced tool, unmeasured, plan 19 N6).

**The act (6.4).** `generate` where the server's capability record lists it, else `analysis`,
logged once per server per session; an unreadable record refuses `act_undecided`. `decide` only
where the server's decide class is enabled, else `decide_not_served` (the code the chaptering
service reads).

**Residency and the lease (13.3).** A local call holds its model under the job's lease: resident →
lease it; not resident → `load-model` with `lease` and the job's load context (today's num_ctx,
LEDGER #111), followed to its end; resident at a smaller context than the call needs and the job
sized a bigger one → reloaded (growth is legitimate, shrinkage never). One lease per server per
job; switching models hands the first back. Heartbeat 40 s; `unknown_lease` marks the hold LOST:
the job's next call on it and `withJobLease` throw `lease_lost` (the plan's "fails the stage
loudly"; BookForge re-leased, Briefcase re-took). Another client's lease pinning OUR model: we run
under it, said in the log. Nothing is ever unloaded. `JobModelLifecycle` is now a face over a
`JobLeases`; the Stories "unload" is a lease release.

**The check before sending (7.2, 0a).** `estimateTokens(prompt) + maxTokens` against
max_model_len, else the job's load context, else the host's `context_ceilings`, else refused
`context_unstated`. Over it: `over_context`, naming model, server and both numbers, nothing sent.
The middle-truncation is gone.

**Replies.** Streamed (`stream: true`, `include_usage`): `[DONE]` or it is truncated
(`unreachable`), a missing `finish_reason` is `protocol_error`, `length` is `truncated` (a hard
failure; the chapter pipeline alone keeps its declared one-chapter degradation by reading that
code), reasoning with no answer is refused as the SDK refuses it.

**Refusals.** `model_not_resident` → one re-ensure. `upstream_unconfigured` → "…has no anthropic key
… Settings › Crucible Servers › <server> › Keys". A 429 passes through as a 429. Busy cards
(`server_busy`, `leased`, `engine_in_use`) come up as `busy` with the SDK refusal as `cause`.

**With P3 (merged).** Every call runs in a lane step: GPU on `hooks.server` only, cloud on the
selected server (the key holder the routing dialog judged Claude against); `submitted`/`leased`
before the next await, `settled` on every end; `streamed` per load event; `beat` per chat and per
second of streamed chunks; `streamDropped` when the load stream's ladder runs out; the hook's
signal on every fetch. `routeOfModelId` reads Crucible ids.

**Routing (6.2).** Options carry `crucibleModel` (`qwen38-27b`→`qwen3.8-27b-4bit`,
`qwen35-9b`→`qwen3.5-9b`, `qwen35-4b`→`qwen3.5-4b`, `sonnet5`/`opus5`→`anthropic/claude-*-5`,
`haiku45`→`anthropic/claude-haiku-4-5-20251001`, `claude-cli*` null) and their `model` IS that id.
The dialog reads `catalogInventory(selected server)`: installed and pullable models are listed,
not-here ones are not, Claude only when that server has an Anthropic key, claude -p always; a
stored choice the server cannot run stays on its row with the server's sentence and is refused by
name at run time.

**Keys (6.6).** On every start and every registry add until done: only the registered row the
pairing file on this computer names; a differing key stops and asks in that server's Keys row
(Keep / Replace); test → put → read the hint back → delete api-keys.json → `keysMigratedTo`. The
OpenAI key is dropped and said so. Any failure keeps the file. MIN_CRUCIBLE is 1.0.32.

## Deviations, and why

1. **`runPlainRequest` takes a fourth, required argument** (`{thinking, maxTokens?, loadContext?,
   job?, timeoutMs?}`). The brief says keep the signature; §6.3 says every call site states
   `thinking`, and the local budget, load context and lease belong to the call site. Required,
   so a caller that forgets is a compile error (Law 10). `runMetadataRequest` is unchanged.
2. **`decide` takes `model`.** The brief's list omits it; `/v1/decide` needs one and the door never
   picks one. The chaptering service's `DecideFn` is satisfied by a two-line adapter at wiring.
3. **Chats are streamed through a raw door**, not the SDK's `chat()`: P3's stall clock needs chunks,
   and the SDK's `chatStream()` drops `finish_reason`. Refusals are rebuilt as the SDK's own types.
4. **The load context is stated by each job** (today's num_ctx sizing, `params.context`), so a
   model is never served at a window nobody chose (#196: the load context is requested per run),
   and P2 keeps today's budgets. P4 owns the numbers.
5. **A lost lease fails the next call and the job** (plan 13.3), not a silent re-take.
6. **Cloud calls go to the selected server** (plan 0 #20's "key-holding server" read as the one the
   dialog judged Claude against). See question 1.
7. **The AI setup wizard is deleted**, not rebuilt (plan 5 replaces it with the doors and the
   routing dialog, which P1 and this phase built).
8. **more-titles runs thinking-off**, as plan 6.3 states; it ran with Ollama's default (on) before.
