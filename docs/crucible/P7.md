### The wire, per chunk

1. `GET /v1/info` once per track: no `denoise` → `voice_isolation_not_offered`; no
   `vocals-roformer` row → `voice_isolation_model_not_offered`; `installed: false` →
   `voice_isolation_model_not_installed`, naming `crucible denoise pull vocals-roformer`. Nothing
   is uploaded before this answers.
2. The chunk's WAV header must say 44,100 Hz (`voice_isolation_input_not_44100`, before upload;
   the server never resamples and its worker would fail the job after the upload).
3. `POST /v1/uploads` (the file streamed from disk with `fs.openAsBlob`).
4. `POST /v1/jobs {type: "denoise", model: "vocals-roformer", params: {}, inputs: {<chunk name>: {blob_id}}, client_ref}`.
   `params` is `{}` because the server forbids every key (PHASE4-AUDIO.md §4.2: "`params` is
   empty, and that is the contract"). `409 env_missing` is relayed with `crucible install rvc`.
5. `409 server_busy` / `409 leased` → the injected **park** gets the holder's line
   (`CrucibleBusy.busyLine` / `CrucibleLeased.leasedLine`) and the operation row shows it. The
   blob is kept (a refused submit never consumes it). Nothing loops: the park decides when to ask
   again, and exactly one submit follows each release.
6. `GET /v1/jobs/{id}/events`: `warming` and `progress` go to the row; `failed` throws
   `VoiceIsolationFailed` with the server's code and message, which Python raises as a
   `VoiceIsolationError` and the run aborts (the noisy original never ships).
7. `GET /v1/jobs/{id}/artifacts/{done.primary_stem}`: the stem the server names (never picked by
   filename here), written beside the target and renamed, after its header is checked against the
   chunk: same rate, same frame count (the server's own invariant, asserted on arrival).
8. Cancel: the workflow ending (a cancel kills the Python process) aborts a signal; the door sends
   `DELETE /v1/jobs/{id}` and reads the stream on to its `cancelled` frame.

**The lease.** Taken after the first chunk of a track (a lease names what is resident and never
loads), heartbeated before each later chunk, released on the track's `separation_release` and
again when the run ends. Failing to take it is a declared mode, logged: the pass is correct
without it, only slower (each chunk would reload the 913 MB checkpoint). Ported from BookForge's
`electron/crucible/denoise.ts`.

## What the real client must provide

`DenoiseClient` in `electron/crucible/denoise.ts` is the whole seam. It is typed as the vendored
SDK (`@crucible/client` 1.0.34) spells its calls, so the SDK's `CrucibleClient` satisfies it
unchanged (the keeper runs one chunk through it), and so does the raw-fetch client in tools/. A
client from P3's transport must provide:

| method | wire | must return | must throw |
|---|---|---|---|
| `info()` | `GET /v1/info` | the SDK's `ServerInfo`: `jobTypes`, and `capabilities[]` of `{jobType, models[{id, installed, resident, vramBytes}]}` | anything; it is relayed as a refusal |
| `upload(blob, {filename})` | `POST /v1/uploads` (multipart, part `file`) | `{blobId}` | |
| `submit(JobRequest)` | `POST /v1/jobs` (`type`, `model`, `params`, `inputs[name].blob_id`, `client_ref`) | the job id | **`CrucibleBusy`** for `409 server_busy` and **`CrucibleLeased`** for `409 leased`, with their `busyLine` / `leasedLine`; **`CrucibleRefused`** (with `status`, `code`, `serverMessage`) for every other refusal. These classes are how the door tells a wait from a failure. |
| `events(jobId)` | `GET /v1/jobs/{id}/events` (SSE) | an async iterable of the SDK's `JobEvent` (warming `{message}`, progress `{fraction, message, extra}`, done `{artifacts, extra}` with the job's own keys, including `primary_stem` and `load_seconds`, under `extra`; failed `{error: {code, message}}`), ending after the first terminal frame | a dropped stream as an error (the door then DELETEs the job and aborts by name) |
| `artifact(jobId, name)` | `GET /v1/jobs/{id}/artifacts/{name}` | the bytes | |
| `cancel(jobId)` | `DELETE /v1/jobs/{id}` | anything | |
| `lease(subject, {act, ttlSeconds})` | `POST /v1/models/{id}/lease` | `{leaseId}` | |
| `heartbeat(leaseId)` / `release(leaseId)` | `POST /v1/leases/{id}/heartbeat`, `DELETE /v1/leases/{id}` | | |

Every request carries the token, `X-Crucible-Api: 1` and `X-Crucible-Client: contentstudio`
(what `/v1/activity` names as the holder). A **work** client must have no per-call deadline: a
deadline would cut off the event stream (client-factory.ts says the same).

The **park** (`ParkOnBusyLane`) is the other injected piece and is P3's to own: called with the
holder's line and the run's abort signal, it resolves when the lane's owner says to ask again.
Until P3 lands, the editor passes `parkOnProbe`: it re-reads the selected server's probe at the
probe's own 15 s cache window until `busyLine` is null. The door is still what decides admission.

Today the editor's client is the P1 factory's SDK `CrucibleClient` on the **selected** server
(`crucibleVoiceIsolation` in denoise.ts, wired in ipc-handlers.ts). Swapping in P3's client is
one line there.

**The reference half was done.** `voice-separator-env` was run by hand, from a scratch script

## Deviations from the plan, and why

1. **The editor's client is the SDK's, not P3's transport.** The brief says the transport and
   lanes are another agent's. The seam is typed so the SDK client already fills it, so the editor
   works now instead of waiting on P3; the raw-fetch client exists to prove the seam is not the
   SDK's by accident.
2. **An interim park.** Plan §9 says a busy lane waits with the holder's sentence. With no P3
   lanes yet, `parkOnProbe` waits on the probe (15 s re-reads). It is declared, not a retry loop:
   one submit per release, and the door refuses anything it does not recognise as a wait.
3. **The silent-chunk passthrough follows the stems' codec.** It was hard-coded 16-bit, which
   matched only the local separator's output. The concat demuxer reads every file as the first
   one's codec, so 16-bit silence among 24-bit stems comes out two thirds as long; the keeper's
   end-to-end check caught it. The silence is now written after the loop, in the first real
   stem's codec.
4. **`voice_separation.py` runs in-process** inside `electron_workflow.py` rather than as a
   subprocess: its requests must reach main on the workflow's own stdout, and the env's
   interpreter it used to run under is exactly what nothing may reach now.
5. **`run_audio_separator.py` is deleted** (it only ran inside the env). The env itself and its
   asset-catalog entry stay for P10, as the brief says; the environment modal still lists it.
6. **The module's version changed** to `1.0.34+7de7dfd8ce35` (4 job types, 5 subjects).
