## The rules, as built

**Lanes (§13.1).** One GPU lane per registered server. A lane has two levels: the **job** (one
admitted queue job per server; the Mac's and the PC's run in parallel) and the **slot** (one GPU
model call at a time, taken by the admitted job's local calls and by standalone calls, which
interleave call by call as they did with the old pool). Cloud (`claude:`, `anthropic/…`, `openai:`)
and `claude -p` take no slot and never wait for the startup sweep. CPU work (ffmpeg, TitaNet,
whisper.cpp until P5) takes nothing.

**Venue (§13.2, #205).** `fast` → `fastServer`; otherwise the selected server. Nothing else: no
rank, no "first that answers". Waits (never fails): nothing selected or pinned (`no_server`),
paused ("… is paused, work waits"), not answering (`unreachable`). Fails: bad token, not a
Crucible, a newer API. A switch the user makes (Select, the pin, the row's Fast toggle) moves work
not yet started; nothing else moves it.

**Parking.** `409 server_busy`, `leased`, `engine_in_use`, `accelerator_busy`, and
`insufficient_memory` *with a measured free figure* park the job with the server's own sentence
(`CrucibleBusy.busyLine`, `CrucibleLeased.leasedLine`, the server message). `insufficient_memory`
"ever" or against the Mac's sized pool fails by name. Each park waits on its own fact, read by the
15 s preflight in a read taken after the park (checked in crucible v1.0.34, `api.py` activity):

| refusal | waits for |
|---|---|
| server_busy, engine_in_use | `slots.accelerated.acceptsWork` true |
| leased | `lease` null. **Not** accepts_work: a lease never changes it on a real server |
| insufficient_memory | `/v1/accelerator` `freeBytes ≥ needed_bytes` |
| accelerator_busy | the named pids gone, unattributed ≤ 1 GiB (the server's `FOREIGN_PROCESS_FLOOR_BYTES`) |

**No loop.** A parked job is offered again only by a preflight read taken after its park. When the
door refused while the last read had already said the fact was clear (the preflight and the door
disagreed), the next re-admission needs an **edge**: a read showing the fact held, then one showing
it clear. So at worst one resubmission per real change on the server, never one per tick.

**Typed contract (Law 10).** `generate-metadata` and `send-held-prompt` answer
`ParkedJobResult {status:'parked', server, holderLine, stage, code}` (wire.ts, mirrored). The row
gains `status:'parked'`, `venue`, `fast`, `parkedLine`, `resumeFrom`, `resumeHeld`,
`resumeShowPrompt`. A resumed job past `transcribe` sends `useSavedTranscripts` for its video rows,
so ASR is skipped; chapters are not stored between runs, so `fields` recomputes them.

**Ledger and sweeps (§13.4).** `<userData>/crucible-in-flight.json`, written synchronously by the
step hooks the moment the server admits a job or a lease. Startup: `sweepAtStartup()` runs as the
app comes up and **gates GPU admission** (`generate-metadata`, `send-held-prompt`, the queue plan and
every standalone local call wait for it). Quit: `before-quit` is held; running jobs are aborted,
given 2 s to release their own leases, then the ledger is swept, 30 s in all. A job's end, a Stop
and a stall each give back that job's rows (chained, so a lease is never released twice). A
dropped stream sweeps its server (`hooks.streamDropped`). Only rows the ledger lists are touched;
an unload is asked for only for a model one of our rows names, and only when `cardHeldBy` says
nobody else is on the card.

**Watchdogs (§13.5).** The 30-minute AI-pool watchdog and the chapter stage's 4 h cap are gone.
Each job runs a 10-minute stall clock, reset by: every completed model call (cloud or local), every
SSE event and decide answer transport reports (`hooks.streamed`/`hooks.beat`), whisper progress,
and each finished chapter step (`reportProgress`). The chapter stage's 60 s "no progress" notice
deliberately does NOT reset it. When it fires: the job's fetch is aborted, its Crucible jobs
cancelled and its lease released, and the row fails with the stall's sentence.

**CLIs.** `generate-metadata-cli.js` and `prompt-harness/run.js` install lanes over the app's
registry and routing (real userData) with their own `crucible-in-flight-<tool>-<pid>.json`, so the
app's startup sweep never releases a live CLI's lease. SIGINT/SIGTERM abort, cancel, release, exit
130/143; a second signal exits at once. A `kill -9`ed run's ledger is swept by the next run of the
same tool.

**Queue UI (inputs page, unfrozen by #205).** The renderer asks `crucible:queue-plan` every tick and
runs what it is told (at most one per server). Progress events carry `jobId` and each row reads
only its own. A parked row shows `parked — <holder line>` in grey (`--text-muted`), with "on
<server>". A **Fast** checkbox sits beside Compilation Mode for new rows; each row has a Fast toggle
until it starts. The **lanes strip** under the queue's progress bar: one chip per server with a
state dot, selected/fast tags, the state in words (the holder's sentence when busy), the resident
model, the parked count and a Running/Paused switch.

## What transport.ts must call

transport.ts (P2's chat/decide/withJobLease) runs **inside `queueAITask`**, which is where the
lanes put the step's context. It reads it with `crucibleStepHooks()` from `electron/crucible/lanes.ts`
(it throws by name outside a lane):

```ts
interface CrucibleStepHooks {
  lane: 'gpu' | 'cloud';
  server: string | null;          // the server a GPU step MUST run on (null for cloud: pick the key-holding server, plan §0 #20)
  jobId: string;                  // the queue job, or '' for a standalone call
  signal: AbortSignal | null;     // aborted by Stop, park, stall, quit: pass it to every fetch
  submitted(row: { server; id; jobType; model }): void;  // SYNCHRONOUSLY right after submit() returns an id
  leased(row: { server; id; model }): void;              // SYNCHRONOUSLY right after lease() (or a load's done carrying lease_id)
  settled(server, kind: 'job' | 'lease', id): void;      // a job reached a terminal state / a lease was released
  streamed(server, jobId, lastEventId): void;            // per SSE event acted on: ledger cursor + stall beat
  beat(): void;                                          // a completed chat, a decide answer
  streamDropped(server, reason): Promise<SweepReport>;   // the reconnect ladder ran out: sweeps that server
}
```

1. **Use `hooks.server`**, never its own choice, for GPU work. Never fall back to another server.
2. **Record before the next `await`**: `submitted`/`leased` right after the server's answer.
3. **Release in `finally`** (the job lease, §13.3) and call `settled`; a run aborted by quit has
   ~2 s to do so before the sweep.
4. **Throw the SDK's refusals unwrapped** (`CrucibleBusy`, `CrucibleLeased`, `CrucibleRefused` for
   `engine_in_use`, `accelerator_busy`, `insufficient_memory`), or wrapped with them as `cause`. The
   lane classifies them by type (`parkRefusalOf`), parks the job and aborts the rest of it. Never
   retry a 409 itself: the queue owns that.
5. **Beat**: `beat()` per completed chat/decide, `streamed()` per SSE event. A non-streamed chat that
   takes more than 10 minutes will stall the job (see the open question below).
6. The `lanes.ts` header's transport note and `docs/crucible/P3.md` are the contract; the keepers'
   `loadStep`/`echoStep` are reference implementations of it.

## Deviations from the plan and the brief

1. **The startup sweep is awaited by GPU admission, not by `app.whenReady` itself.** `whenReady`
   starts it and every AI door (`generate-metadata`, `send-held-prompt`, the queue plan, standalone
   local calls) awaits it, so no `generate-metadata` is accepted before it settles. Blocking
   `whenReady` would hold the window for the full 15 s deadline on every launch while a ledger row
   names an asleep PC, and nothing non-AI may wait for Crucible (§0a).
2. **Leased parks wait on `lease`, not `acceptsWork`**; VRAM parks wait on `/v1/accelerator`.
   `acceptsWork` does not change for a lease or foreign VRAM (v1.0.34 `api.py`), so waiting on it
   alone would re-admit at once and park again every 15 s: a loop.
3. **The fake's `accepts_work` no longer counts a lease**, to match the real server.
4. **`stream-reconnect.ts` is not ported.** Nothing in ContentStudio follows an SSE stream until P5
   (asr) / P7 (denoise); porting it now would be code with no caller. `hooks.streamed` keeps the
   `lastEventId` it will resume from, and `hooks.streamDropped` is the sweep it ends with.
5. **One running job per server (P3b) is built now**, not after P3.
6. **The CLIs need a selected Crucible server for local calls**, as the app does: before P2 lands,
   their local calls still go to Ollama, but through the selected server's slot.
7. **Until transport.ts lands, the venue is bookkeeping only**: every local call still goes to this
   Mac's Ollama whatever lane it holds. With a fast server pinned, a Mac job and a "PC" job could
   then both load Ollama here at once. Nothing is pinned fast by default; the join at merge closes it.
8. `episode-splitter.service.ts`'s retired `analyze()` called `queueTranscription`; it now calls
   whisper directly (its progress listener was already what reported).
9. makeRequest's comment that "the AI queue re-wraps every rejection" (ai-manager.service.ts) is now
   stale: `queueAITask` passes errors through with their types. The comment sits in a request
   branch this phase does not touch; the matching comments in `cancellation.ts` and
   `metadata-generator.service.ts` were corrected.

## Open questions for Owen

1. **The stall window vs one long call.** The plan's 10 minutes counts a completed chat as the sign
   of life. The whole-transcript chapter call on a long podcast is one call (the chapter stage has
   clocked 516 silent seconds of model load alone). If transport's chats are not streamed, that
   call can exceed 10 minutes and be cancelled. Stream the chapter call's tokens, or raise the
   window for it (a declared, named exception)?
2. **VRAM parks' floor.** Re-admission after `accelerator_busy` uses the server's 1 GiB
   `FOREIGN_PROCESS_FLOOR_BYTES`, copied into ContentStudio. Better as a Crucible fact ("would a load
   of X be admitted now"), asked for as a §19 item?
3. **Parked rows after an app restart** lose main's park record and are re-decided (submitted once,
   and parked again if still busy). Keep, or persist parks?
4. **A scratch-userData switch for agent launches.** main.ts pins userData to
   `~/Library/Application Support/contentstudio`, so an agent cannot launch the app without touching
   Owen's data. A declared dev-only override (an env var, logged loudly at start) would make live
   app runs safe. Wanted?
5. **The fast pin and Ollama until P2 merges** (deviation 7): should the Fast toggle stay hidden
   until transport joins?
