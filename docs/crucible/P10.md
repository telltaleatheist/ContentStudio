## 3. Stems are 16-bit PCM WAV, and nothing else is read

**The LEDGER has no entry recording the 16-bit WAV change**, so it was checked in the source of
the Crucible the Mac runs (`~/.crucible/installation.json`: release **1.0.40**), read only:

- `crucible/jobs/denoise/__init__.py`: `OUTPUT_FORMAT = "WAV"`, sent with every separate request.
- `crucible/jobs/denoise/worker.py`: the format is set on both the separator and its model
  instance per request (the comment names ContentStudio's FLAC stem on 1.0.38 as the bug), and a
  stem in any other container fails the job ("the stem container is part of the contract").
- The rvc env's `audio_separator/separator/common_separator.py` `write_audio_pydub` casts to
  `np.int16`: the WAV is 16-bit.

So `electron/crucible/denoise.ts` now: refuses a primary stem whose name is not `.wav` before
fetching it (`voice_isolation_stem_not_wav`); reads it with `readWavFormat` (which now also
reports the format tag, extensible sub-format and bits); refuses anything but 16-bit integer PCM
(`voice_isolation_stem_not_pcm16`); and writes it at exactly the path Python asked for.
`voice_separation.py` writes silent passthrough chunks as `pcm_s16le` WAV (`STEM_CODEC`) and
no longer probes a stem's codec. The fake's denoise returns a 16-bit WAV of its input, as the
real worker does (a 24-bit chunk keeps each sample's top two bytes).

## 4. The retired-file cleanup

`electron/retired-components.ts`, wired in `main.ts`; Briefcase's
`backend/src/components/retired-components.ts` is the pattern.

- **When:** 15 s after boot, in the background (an unref'd timer), never awaited by boot.
- **What it looks for** (fixed paths, no globs):
  - `<userData>/components/{whisper-engine, whisper-tiny, -base, -small, -medium, -large-v3, -large-v3-turbo}/`
    and their records in `<userData>/components/installed.json`;
  - in each store the editor's asset manager can have written (the OwenMorgan shared dir, and
    its per-app fallback `<userData>/assets`): `models/whisper/ggml-{tiny,base,small,medium,large-v3,large-v3-turbo}.bin`,
    `runtime/voice-separator-env/` (only when it has `audio-separator-models/` or
    `conda-meta/`), and their records in that store's state file
    (`<shared>/autocutstudio/installed.json` or `<userData>/assets/state/installed.json`).
    `models/whisper` and `models` are removed afterwards only if empty.
- **The path assertion** (`assertRemovable`), at plan time and again immediately before each
  `rm`/`unlink`: strictly inside its declared parent, strictly inside `userData` or the shared
  dir, and neither is, contains nor sits inside anything this build uses (`components/ffmpeg`,
  `components/speaker-embedding`, `runtime/autocutstudio-env`, `managed-bins/ffmpeg-tools`). A
  failure is an error for that path, never a removal. A symlink is unlinked, never followed. A
  record whose path points elsewhere is left alone and logged. Ollama's store, `~/.crucible`,
  BookForge's `llama-models` and every other shared slot are never looked at.
- **Dry run first:** every run logs the whole plan (`[retire] would remove <size> <type> <path>
  [<reason>]`, the total, the records it would drop, and what it leaves alone and why) before it
  removes anything. `node tools/retire-dry-run.js` prints the same plan for a machine and writes
  nothing (it computes the shared dir without creating it).
- **Opt-out:** store key `keepRetiredComponents: true`. The plan is still logged; nothing is
  removed or recorded.
- **Once:** completion is recorded in the store under `retiredComponents["p10-crucible"]`
  (`completedAt`, `bytesFreed`, `removed`, `droppedRecords`); a later launch skips it. A run
  with any failure, or a state file that cannot be parsed, is not recorded and is tried again
  at the next launch.

## 5. A clean install downloads no Ollama, whisper.cpp or separator env

Read from the installer and download code as it now stands:

- **The app's components** (`electron/components/catalog.ts`): `ffmpeg` (required) and
  `speaker-embedding` (optional). Startup (`EnvironmentSetupService.initialize`) enqueues only
  `readiness.transcription.missingRequiredTools`, which `get-startup-readiness` builds from
  `['ffmpeg']`. Settings' download list is the same catalog.
- **The editor's assets** (`electron/services/editor/asset-catalog.ts`): `ffmpeg-tools` and
  `python-env`, both required; `assets:ensure-required` installs exactly the required ones.
- **The package** (`package.json` `build`): `files` and `extraResources` carry no whisper-cli,
  model or env (the `editor-backend/utilities/bin` resource is gone).
- **Build scripts:** `download:all:<target>` stages ffmpeg/ffprobe only; there is no whisper
  download script.
- **Ollama:** no code, script or setup step installs, pulls or starts it (`setup.sh` names
  Crucible instead). Every model runs on Crucible, which the app connects to and never bundles.
- `npm run check:legacy-gone` loads the built catalogs and fails if either offers an id or URL
  naming whisper, ggml, a separator or Ollama. At this commit: app catalog `ffmpeg,
  speaker-embedding`; editor catalog `ffmpeg-tools, python-env`.
