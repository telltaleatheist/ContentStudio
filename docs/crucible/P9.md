## What exists

`electron/services/metadata/reroll/`

| file | what it does |
|---|---|
| `types.ts` | the decide wire (restated, not imported from chaptering), fields, rules, `GateError` |
| `decide-read.ts` | the floor rule, **copied** from `chaptering/assign.ts` (`readYesNo`, `readChoiceDistribution`, `wireOptions`); `check:reroll` holds the copy to the original's answers |
| `rules.ts` | `FIELD_RULES`, the state, one yes/no **statement per rule per unit, quoting the unit**, question names `u<i>_<rule>`, ≤64 questions per decide, the re-roll prompt, the description sentence splitter (byte-exact round trip) |
| `checks.ts` | ask and read; per-rule pass score `1 - max(0, P(yes) - baseline)`; the per-video baseline (median, capped, frozen from the first reading; declared off) |
| `ranking.ts` | a `choice` over ≤26 titles, asked once per **rotation** so a letter/position bias cancels; options named by position; reported as `relative` = p × n (1.0 = a fair share: the per-video baseline) |
| `gate.ts` | per field: score every unit; failing units go back grouped by their first failing rule, one call per rule per round, **at most 3 rounds**; each unit keeps its best-scoring attempt; what still fails ships with a warning naming the rule |
| `settings.ts` | `rerollGate` on/off, `rerollGateTuning` (maxRerolls ≤ 3, thresholds per `<field>.<rule>`, baseline); bad values throw by name |
| `reroll.service.ts` | the binding: fields off the item (link block held back by exact match, chapter titles by position, hook + description sentences), decide on `REROLL_SCORER_MODEL` through `transport.decide` on the GPU lane under the job's leases, re-rolls on the field's own routed model through `runPlainRequest`, record + trace + warnings |

Rules per field (`FIELD_RULES`): titles — creator, narrates, nonsense; chapters — creator, narrates,
sentence, nonsense; description (hook + sentences) — creator, first_person, narrates, nonsense;
thumbnail text — creator, nonsense; pinned comment — creator_third_person, nonsense.

**Wiring.** `metadata-generator.service.ts`: one call after `scrubGeneratedItem`, before the save.
Settings read at job time in the generation IPC (`rerollGate`, `rerollGateTuning`; absent = the
declared defaults). Every decide, every re-roll and the ranking are appended to `_prompt_trace`
with their answers; `reroll_gate` on the item holds the settings, every unit's attempts and
readings, the ranking and the warnings; the warnings also go to the run's. Gate off: the item
records `{mode: 'off'}` and nothing is asked. The reports page shows each generated title's rank
(`#1`…, top three in ink, the relative share in the tooltip) and any rule a title still fails.

**The scorer** is a fixed declared role, `REROLL_SCORER_MODEL = 'qwen3.5-9b'` in
metadata-routing.ts, beside `SUMMARIZATION_MODEL` (not a dialog row: the thresholds were measured on
this model, and no cloud model can answer a decide).

## Calibration (the 9B, Mac Crucible 1.0.38, through `transport.decide`)

Tool: `tools/reroll-calibrate.js` (`rules --set … [--only-labelled] [--rules …]`, `rank`, `report`).
Its own temp registry (one server, the local Crucible; never the app's userData), a lease per batch
of groups, released after; it waits its turn on a busy card. Raw readings are kept in
`docs/crucible/p9-calibration/`. Throughput on the shared card: 1.3–2.8 s per question (P8a
measured 0.65–1.0 alone).

**Hand labels.** `tools/fixtures/titlecheck/labels.jsonl`: 50 chapter titles and 20 descriptions,
sampled with a fixed seed (half from what the scrub, the judges or Owen had touched), labelled
against LEDGER §1 **before** any model read them (commit 2a47061). A description fails a rule when
any of its sentences does.

**The baseline trap (§0a) was real, and was fixed at the source.** v1's narrates statement put a
median P(yes) of 0.73 on CLEAN chapter titles (0.65 on clean description sentences). A per-video
median cannot tell "this model leans" from "this video's titles are all narrated", so instead the
statement was rewritten until clean titles sat low (v4, "the one doing the action is the video
itself or the person presenting it (as in …)"). The baseline machinery is built and keeper-tested
and ships with `baselineCap: 0` (off).

**The gate's verdict** at the declared thresholds (creator P>0.7, first_person P>0.5, narrates
P>0.8, nonsense P>0.5, sentence not gating): **61 of 62** labelled items agree (22/22 violators
caught, 1 false alarm in 40: *"The 'theory in crisis' claim about Darwin and the fossil record,
refuted"*). 8 description labels lack their v4 narrates reading (stopped). The thresholds were
picked on the same 70 labels they are scored on; the corpus run below is what checks them on
unseen text.

## Deviations from the brief

1. **Re-roll per unit, not per field.** A title, chapter title, description sentence, thumbnail
   text or pinned comment that fails goes back; the rest of its field is untouched. A field's
   "best candidate under the threshold" rule would never re-roll a ten-title list with one bad
   title (the pick-field bar says weak candidates are fine) and would throw away nine good ones
   when it did. Owen's words were "everything that scores under 0.5 gets sent back".
2. **The re-roll is a revision call** (the failing entries in, the same count out, the rule named in
   positive form), not a fresh generation of the whole field: it is the one form in which Law 4
   lets a wrong form be shown, and it keeps the passing entries. It runs on the field's routed
   model with thinking on, as the scrub was measured.
3. **`sentence` is measured but never gates** (threshold 0; Owen, #211).
4. **No whole-text description format rule.** The description is judged sentence by sentence (so a
   failing sentence can be quoted and re-rolled alone); "no first person" is its format rule.
5. **Compilation items are not gated** (the scrub does not cover them either).
6. **The gate ships off** (above).

## Owen's answers (LEDGER #211) and what changed

1. **Chapter titles are sentences:** "one or two sentences describing what's being discussed, how
   YouTube expects them to appear in the description". `sentence` never gates (threshold 0).
2. **"X, refuted" / "X, mocked line by line" is a fine format, not narration.** The `narrates`
   statement now says so, with two examples of the format (reroll.yml `rules.narrates`).
3. **Descriptions may carry calls to action**, and a CTA is not a reference to the creator. The
   `creator` statement now says so (`rules.creator`).
4. On all three: "they're coming out fine as is. don't change the prompts." No generation prompt
   changes on the gate's account; only the gate's rule statements and hand labels moved. The blind
   labels already had all six affected items clean on these rules (de09, de13 for creator; ch05,
   ch32, ch34, ch36 for narrates); each now carries `ruled_by: "Owen, LEDGER #211"`.
5. **The ranking threshold** for showing the rank by default is decided when the A/B run is in.

**The two reworded statements are UNMEASURED.** The v1/v4 numbers above are for the wording
before #211; the thresholds stand until the re-measure below.
